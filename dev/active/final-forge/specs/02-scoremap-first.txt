Build a standalone reference screen for an existing Streamlit application called BidPilot. It is a B2G pursuit workbench for bid leaders. Preserve the existing product logic and data contract; this reference defines only information architecture and interactions.

The core job is to transform a public tender evaluation matrix and supplier operating profile into a winning bid strategy and proposal workspace. The first viewport must make the official score mechanics visible: tender, buyer, evaluation criteria and weights, supplier readiness, gaps, and the current PURSUE decision. A judge must immediately see that this is more than document summarization.

Use a score-map-first workspace. The central surface is a compact evaluation matrix with criterion, weight, readiness, supporting supplier asset, gap, and planned claim. Selecting a row opens its proposal section blueprint and required proof. A persistent side region shows tender source snapshot, supplier profile, pursuit status, deadline, contract value, and four decision dimensions: eligibility, capacity, commercial fit, and evidence strength.

Provide three selectable Win Positions derived from the matrix. Each option must display its statement, proof cards, weakness, and mitigation. The selected position drives a visible proposal blueprint, generated draft preview, red-team findings, owners, tasks, and a persisted Bid Room run with replay. Include one clear primary action to build the strategy-led proposal and visible states for loading, REVIEW, NO-GO, and an existing saved run.

Use English copy. Use only supplied SEED Design tokens and components. Do not use external fonts, gradients, decorative charts, fake AI chat, or invented customer metrics. Desktop 1440, tablet 768, and mobile 390 must have zero horizontal overflow. On mobile, convert the matrix into readable criterion cards while retaining weights and gaps. Accessibility: semantic headings, visible focus, keyboard-operable row and strategy selection, explicit status text, and WCAG-friendly contrast.
