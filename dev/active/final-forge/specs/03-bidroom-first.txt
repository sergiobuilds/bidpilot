Build a standalone reference screen for an existing Streamlit application called BidPilot. It is a B2G pursuit workbench for bid leaders. Preserve the existing product logic and data contract; this reference defines only information architecture and interactions.

The screen represents a saved Bid Room where a bid team moves from tender intake to decision, strategy, proposal draft, red-team review, and owned work. The first viewport must show continuity and execution: source snapshot, selected supplier, pursuit status, selected Win Position, proposal progress, open red-team findings, owned tasks, and saved run identity. A judge must understand that one run connects every stage.

Use a bid-room-first workspace with a short stage navigator for Intake, Qualify, Position, Draft, Review, and Assign. The active stage is Position, but the page must summarize completed and pending stages. The main region shows the selected Win Position with proof cards, weakness, mitigation, and its connection to official evaluation criteria and weights. A companion activity region shows the run trace and task ownership without pretending that local events are authenticated Snowflake or CoCo events.

Include a compact pursuit decision panel with eligibility, capacity, commercial fit, and evidence strength; three selectable Win Positions; evaluation score map; proposal blueprint; generated draft preview; red-team findings; and replayable persisted run. The primary action is Build proposal from selected strategy. Include realistic loading, empty, REVIEW, and NO-GO states. Do not add collaboration, notifications, or chat capabilities that do not exist.

Use English copy. Use only supplied SEED Design tokens and components. Do not use external fonts, gradients, decorative charts, fake AI chat, or invented customer metrics. Desktop 1440, tablet 768, and mobile 390 must have zero horizontal overflow. Mobile must turn the stage navigator into a compact progress control and keep the primary action reachable. Accessibility: semantic headings, visible focus, keyboard-operable stage and strategy controls, explicit status text, and WCAG-friendly contrast.
